# Windows installer identity

`installer-template.nsi` is the official Tauri CLI 2.12.4 NSIS template under its MIT license. `NSIS_UPSTREAM.json` records the pinned upstream file and SHA-256. Changes preserve the previously shipped `Drift` registry product name and `Software\drift` manufacturer key while allowing the visible product name to be `Driftnet`, and remove the directory picker because privileged helpers require a protected installation.

Do not change those registry constants when renaming the displayed product. The original installer uses them to recover the installation directory, identify upgrades, and remove the existing uninstall entry. Keeping them avoids duplicate installations. Per-user rules retain the `app.drift.desktop` configuration directory. Hooks remove former shortcuts only when their targets match this installation, stop the existing service through the OS service controller, and install the replacement service.

The installer and service accept only the Windows known-folder Program Files path with the direct `Driftnet` or legacy `Drift` directory. Both verify trusted ownership, absence of reparse points, and access controls that forbid unprivileged writes, deletion, ACL changes, and ownership changes. The installer checks the tree from its protected parent downward before copying or executing payloads. Unsafe older custom installations fail closed and require removal before reinstalling. No existing helper executable is run to stop or remove the service.

`validate-install.ps1` is embedded in installer and uninstaller code through `validator-embedded.nsh`. Regenerate it with `python3 scripts/embed-windows-validator.py`; CI checks that the readable and embedded copies match. The service repeats the path/ACL check when registering and starting, so directly invoking a copied helper from a writable directory cannot create a LocalSystem service.

When updating `@tauri-apps/cli`, refresh this template from that exact upstream tag, preserve the registry identity and protected-path changes, and run the native Windows installer integration job. Its legacy registry/shortcut fixture verifies in-place migration, configuration preservation, and one uninstall entry. That fixture is a migration test, not a claim that an older signed installer or Windows 10 GUI was exercised.
